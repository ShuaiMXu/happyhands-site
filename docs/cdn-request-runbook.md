# CDN request budget and availability

The November 21 Vercel notice reported 90% of the Hobby team's 1M request allowance. That was an alert threshold, not a current balance, a deadline, or an attribution to a specific URL. A healthy homepage proves availability at check time, not remaining quota.

1. **P0: Verify service and headroom.** Check the public portal and the Vercel team Usage → CDN Requests. Record the exact count, timestamp, and reporting window. If the site cannot tolerate a pause and usage is still nearing the cap, have the owner review the available plan and spike-protection terms in Billing; do not treat a pending performance PR as continuity protection. Upgrading or buying capacity is a separate decision.
2. **P1: Find the production traffic driver.** In the project CDN Requests Routes view, filter to Production and compare equal windows before and after site PR #103. Record the archive index, unified index, covers and preview requests with total volume. The older all-environment sample does not identify today's cause. If a route is still out of proportion, check Firewall Traffic for user-agent and path concentration before changing policy.
3. **P1: Remove confirmed duplicate page requests.** The homepage loads the same list index and cover map on Systems and Components. This PR reuses the completed pair in the same browser document for up to 60 seconds. Cold loads, explicit retries, and source verification keep their existing behavior. It does not add shared HTTP caching or change legacy/client API behavior.
4. **P2: Fix the next measured source, not every possible one.** If repeat visits dominate, measure an HTTP browser freshness change on the list endpoints, including source-integrity behavior across deployments. If covers/preview assets dominate, use viewport-aware loading based on a request trace. If identified automated callers dominate, evaluate a narrowly scoped mitigation, with verification that legitimate visitors, SEO crawlers and Agent/MCP clients keep access. Do not blanket-block clients.
5. **Confirm after rollout.** Compare the same exposure windows, with top routes, counts, and page-navigation request traces. Check portal, resource detail, Studio and registry access before claiming savings. Revert the frontend change if freshness or functionality regresses; do not remove the last working deploy as an emergency measure.

References: [Vercel CDN usage](https://vercel.com/docs/manage-cdn-usage#cdn-requests), [Traffic view](https://vercel.com/docs/vercel-firewall/firewall-observability#traffic), [Pro CDN tiers and spike protection](https://vercel.com/changelog/flat-rate-cdn-is-now-ga-for-pro-teams).
