# Collection catalog import

The supplied COLLECTIONS.md lists ten archives; the catalog also retains the existing Cult UI component library as an eleventh collection. This import reuses existing website/style references, Design.md documents and original system assets, then adds Ottermind references, mobile tokens, platform documents, supplied Meridian derivatives and Mobbin's public integration documents. It does not claim paid app screenshots, application-page structure knowledge, or universal target-framework compatibility.

Run `npm run catalog:build`, then `python3 scripts/import-collections.py /absolute/path/to/the-supplied-workspace`. The source directories are read only. Existing published assets are reused; new original archives live under `public/collections`. Supported source files, licenses/notices and media retain original bytes. Errors/log dumps and executable gallery HTML are not published or executed.

`public/resources/v1/index.json` contains stable IDs, type, collection, platform/system, source/license notice, exact source bytes/hash, preview links and installation metadata. The website browser and Harness resource MCP consume the same catalog. Counts derive from actual indexed resources, not README marketing totals. A collection overview is indexed separately and does not inflate its displayed count. Index search does not imply that every supporting CSS/font file is an independently classified component.

Supplied branded registry originals remain under `public/collections/brand-registry`. Separately derived `/r/meridian-*/` payloads replace the supplied localhost host with the official website URL, including source-file URL references. Original payload hashes and the transformation scope are recorded. Original system/component source is not overwritten. Referenced fonts are copied to `/fonts/` and have public CORS headers for consumers. Package installation remains a deliberate target-project action; the site never runs a registry payload.

The inline Collections panel reuses the same resource navigation, ResourceCard, ResourceToolbar and detail heading as existing pages. It is available from the homepage and resource browser without a second page hop. Document preview loads the full hash-checked source. Supported Design.md components use the existing reconstructed specimen renderer; token samples show actual supplied values. Neither is a claim of original component execution. Component payloads remain readable/downloadable source with installation metadata.

Validation includes every indexed source hash and byte count, all collection counts, existing-asset reuse, derived registry dependency paths and original-payload preservation. Browser checks cover normal desktop/phone layouts, both themes, Chinese/English, token samples, full references, keyboard filtering, empty results, source failure/retry and the inline homepage panel. Static checks are not independent design acceptance.

The core `docs/resource-mcp.md` describes stdio configuration and the real source handoff: MCP search/read → existing resources select → experience audit and source adaptation → design decision → isolated repair → independent review → human judgment. Discovery does not auto-adopt a design or approve a page.
