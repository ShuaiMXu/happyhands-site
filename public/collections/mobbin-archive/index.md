# Mobbin

Mobbin is a searchable library of real mobile apps, web apps, and websites. Product designers, developers, and AI agents use it to research how shipped products handle screens, UI patterns, website sections, and multi-step user flows.

## What you can research

- Individual mobile and web screens.
- End-to-end flows such as onboarding, checkout, account setup, and subscription.
- UI patterns and elements such as dialogs, navigation, forms, tables, empty states, and paywalls.
- Website sections such as heroes, pricing, testimonials, navigation, and footers.
- Examples from named products, platforms, industries, and app categories.

## Why Mobbin

- References come from real shipped products rather than speculative concepts.
- The library covers isolated screens and the ordered flows around them.
- Search spans mobile apps, web apps, websites, screen text, patterns, and UI elements.
- New content is added weekly.
- References can be saved to collections and copied into Figma on eligible plans.

## Ways to use Mobbin

### Browse on the web

Explore the library at https://mobbin.com/explore. A free account provides limited access. Paid plans unlock the full library, search, flows, animations, and additional features.

Mobbin MCP lets compatible AI tools search the library using natural language and return screen images in their tool responses. It is available on Pro, Team, and Enterprise plans.

- API quick start: https://docs.mobbin.com/api/quickstart

## How agents should use Mobbin evidence

Treat Mobbin as evidence of how real products are designed, not proof that a pattern improved performance. Compare multiple examples, preserve source links, distinguish observation from inference, and adapt findings to the user's brand, design system, accessibility requirements, and product constraints.

When reporting findings, identify the referenced product, describe what is visibly present, and include the canonical Mobbin URL. Check capture metadata when the user needs current examples.
